# Архитектура

Проект не форкает Picus и не превращает ACIR в R1CS. Это адаптер между Noir
artifact JSON и Picus SMT: из Picus берётся только `picus-smt` (IR запроса
однозначности и бэкенды cvc5-ff / z3). Алгоритм уровня QED²/DPVL —
пропагация лемм вперемешку с SMT-запросами — реализован здесь заново, на
идиомах ACIR, потому что `picus-analysis` работает только с R1CS.

Есть два независимых пути, и они отвечают на один вопрос — может ли цель
принять два значения при одинаковых входах — с разных сторон.

## Статический путь: `scan`

```text
Noir artifact JSON
  -> acir::Program / acir::Circuit                      artifact.rs
  -> выбор fixed witnesses и целей                      targets.rs
  -> перевод поддержанных ACIR opcodes в Picus IR       translate/
  -> пропагация однозначности (леммы, без солвера)      translate/uniqueness.rs
  -> уточнение: локальные окна <= 64 ограничений,       refine.rs
     UNSAT на окне доказывает однозначность и снова
     кормит пропагацию
  -> релаксированный UniquenessQuery                    solver.rs
     (UNSAT здесь уже доказывает verified)
  -> точный UniquenessQuery (только он даёт unsafe)
  -> сертификат: контрпример перепроверяется по ACIR    dynamic/certify.rs
```

Слои упорядочены по цене. На реальном выводе компилятора основную работу
делает пропагация: хорошо скомпилированная схема определяет почти каждый
witness, и SMT-запрос строится только для немногих, которые леммы не закрыли.

Для каждой цели строится self-composition query:

```text
exists W1, W2:
  SemACIR(W1)
  SemACIR(W2)
  fixed witnesses совпадают
  целевой witness отличается
```

- `SAT` на точном срезе: цель недоограничена;
- `UNSAT`: цель однозначно определяется поддержанной ACIR-семантикой;
- `UNKNOWN`: солвер не решил за отведённое время;
- `UNSUPPORTED`: на цель может влиять непереведённый opcode.

### Перевод ACIR

- `AssertZero(Expression)` — linear/nonlinear Picus constraints.
- `RANGE` — boolean для `num_bits = 1`, `x = Σ 2^i b_i` для ширин меньше поля
  (шире `--max-range-bits` отбрасывается как релаксация), no-op для ширин не
  меньше битности поля.
- `AND`/`XOR` — через битовое разложение входов и выхода.
- `MemoryInit`/`MemoryOp` — one-hot селекторы индекса (частично).
- Остальные blackbox (хэши, кривые, подписи) — абстракция детерминизма:
  равные входы ⟹ равные выходы. `verified` под ней корректен, `unsafe` может
  быть ложным и потому перепроверяется сертификатом.
- `BrilligCall` — недетерминированный источник; его выходы можно проверять как
  цели.

Непереведённые opcodes не игнорируются молча: граф зависимостей блокирует только
цели из затронутой non-fixed компоненты. Подробно — в [SOUNDNESS.md](SOUNDNESS.md).

## Динамический путь: `fuzz`, `mutate`

```text
входы (сгенерированные или seed)                        dynamic/fuzz.rs
  -> исполнение в ACVM с ремонтом входов                dynamic/concrete.rs
  -> подмена одного выхода Brillig, честное             dynamic/concrete.rs
     исполнение остального                              dynamic/candidates.rs
  -> ремонт witness по ограничениям (mutate)            dynamic/repair.rs
  -> сертификат по всем опкодам, blackbox вычисляются   dynamic/certify.rs
```

Находка динамического пути — две полные раскладки с одинаковыми параметрами,
разными выходами и выполненными ограничениями. От перевода она не зависит.
Отсутствие находок ничего не доказывает.

## Карта модулей

| Путь | Что там |
| --- | --- |
| `src/lib.rs` | дерево модулей и `run()` |
| `src/cli.rs` | аргументы clap и их преобразование во внутренние enum |
| `src/commands/` | по модулю на подкоманду: `scan`, `fuzz`, `mutate`, `unpinned`, `witness` (`feasible`, `witness-inputs`, `check-witness`) |
| `src/artifact.rs`, `src/debug_info.rs` | загрузка артефакта, ABI, отладочные символы |
| `src/targets.rs`, `src/report.rs` | выбор целей, формат отчёта |
| `src/translate/`, `src/solver.rs`, `src/refine.rs` | статический путь |
| `src/dynamic/` | динамический путь и сертификат |
| `src/field.rs` | преобразования `FieldElement` ↔ `BigUint` / десятичная строка |
