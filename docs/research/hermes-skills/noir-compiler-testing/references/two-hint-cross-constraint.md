# Two-Hint Cross-Constraint — ложная находка (cautionary tale, 2026-08-22)

**Это НЕ бага компилятора.** ACIR корректно отражает то, что написал
программист. Программист не дописал `assert(h1 == a)`, и ACIR честно
даёт две степени свободы. Компилятор не угадывает намерения.

## Чем опасна эта ложная классификация

Адаптер находит второй witness, сертификат проходит (2 opcode),
контроль работает. Всё выглядит как находка. Но:

```
ACIR: BrilligCall → [w2, w3]    // h1, h2
      AssertZero: w2 + w3 = 0    // h1 + h2 == 0
```

Уравнение `w2 + w3 = 0` имеет p решений (для любого w2 = x, w3 = p-x).
ACIR **корректен** — он проверяет ровно то, что написано в исходнике.

## Три проверки (обязательны перед объявлением баги)

| Проверка | Результат | Вердикт |
|----------|-----------|---------|
| ACIR верен источнику? | `h1 + h2 == 0` → `w2 + w3 = 0` ✅ | Не потеряно |
| Сертификат прошёл? | 2 opcode, Certified ✅ | ACIR считает значение свободным |
| Контроль: честный → rejected? | ✅ | Не вырожден |

**Ключевой вопрос:** программист написал `assert(h1 + h2 == 0)`.
ACIR содержит **ровно это ограничение**. Где бага компилятора?
Её нет. Программист просто не написал `assert(h1 == a)`.

## Программа-триггер (для ознакомления)

```noir
unconstrained fn hint_a(x: Field) -> Field { x }
unconstrained fn hint_b(x: Field) -> Field { x }
fn main(a: Field) -> pub Field {
    let h1 = unsafe { hint_a(a) };
    let h2 = unsafe { hint_b(a) };
    assert(h1 * h2 == 0);  // две степени свободы
    h1
}
```

Компилятор: exit 0, 0 `bug:`. Адаптер: 3-4 находки.
**Не бага. Не публиковать.**

## Почему чекер молчит (и это ок)

Чекер `check_for_missing_brillig_constraints` — эвристика.
Он видит:
1. `constrained_values.len() == 2` → `is_against_const = false`
2. `arguments_intersect` → true (оба хинта берут `a`)
3. Решает: **«пересечение есть → достаточно ограничено»**

Это консервативное поведение эвристики. Оно может пропускать слабые
ограничения — и это **известное ограничение**, а не бага.
