# Недоограниченность, которую компилятор Noir не помечает: среднее при пустом наборе

## Суть

Схема доказывает утверждение «мой средний балл не ниже порога», не раскрывая
оценок. Среднее вычисляется подсказкой и проверяется ограничением

    assert(avg * count == total);

При `count = 0` сумма `total` тоже равна нулю, и ограничение принимает вид
`avg * 0 == 0`. Оно выполняется **для любого** `avg`. Частное перестаёт быть
закреплённым, и доказывающий заявляет какое угодно среднее.

Смысл в прикладных терминах: **предъявляется доказательство «мой средний балл 100»
при полном отсутствии оценок.**

## Почему это опасно на практике

1. **Компилятор молчит.** У Noir есть выделенная проверка недостающих ограничений
   для подсказок (`check_for_missing_brillig_constraints`). Здесь она не
   срабатывает: синтаксически подсказка ограничена, ограничение на месте.
   Разработчик, доверяющий компилятору, получает ноль предупреждений.

2. **Обычное тестирование не проявляет дефект.** Честный доказывающий выполняет
   подсказку, та при `count = 0` возвращает 0, и проверка порога отклоняет вход.
   Тесты зелёные. Дыра видна только тому, кто подменит подсказку.

3. **Подсказка целиком под контролем злоумышленника.** Для атаки НЕ нужно менять
   проверяемую часть схемы: `unconstrained fn` не проверяется, это собственный код
   доказывающего. В воспроизведении ниже изменена ровно одна строка внутри
   unconstrained-функции.

## Воспроизведение

Честный прогон:

    scores = ["95","91","90","0","0","0","0","0"], count = "3", threshold = "90"
    -> Circuit output: 92          (верно: (95+91+90)/3 = 92)

Честная попытка обмана (пустой набор):

    scores = все нули, count = "0", threshold = "90"
    -> Failed assertion            (подсказка вернула 0, порог не пройден)

Атака. В unconstrained-функции заменяется одна строка:

    if count == 0 { 0 }   ->   if count == 0 { 100 }

Проверяемая часть схемы не меняется. Тот же вход:

    scores = все нули, count = "0", threshold = "90"
    -> Circuit output: 100         <-- ПРИНЯТО

## Контроль

В исправленную схему добавляется одна строка:

    assert(count != 0);

Та же атака против неё:

    -> Failed assertion            <-- отвергнуто

Контроль обязателен: без него нельзя отличить настоящую дыру от ошибки стенда.

## Что говорит компилятор

    nargo compile --force
    предупреждений о недоограниченности: 0

## Что говорит наш механизм

    noir-picus-adapter mutate target/avg.json --witness target/w0.gz --attempts 8

    находок: 4, опровергнуто: 377
    цель w10 (возвращаемое значение): original=0, alternative=1
    при тех же зафиксированных входах

То есть механизм показывает существование второго свидетеля, отличающегося
значением ВОЗВРАЩАЕМОГО значения при полностью зафиксированных входах — это и
есть определение недоограниченности.

## Оговорка о классе

Это не ошибка компиляции: ACIR соответствует исходному тексту. Это **пробел
проверки**: выделенная проверка компилятора не распознаёт ограничение, которое
вырождается на части входов. Опасность в том, что проверка создаёт ложное чувство
безопасности — она есть, она включена по умолчанию, и она молчит.

Класс подтверждён нашими прежними находками (см. соседние каталоги
`non-pinning-constraint-silences-checker`, `predicated-constraint-silences-checker`):
8 из 8 построенных случаев механизм ловит, компилятор молчит на всех.
